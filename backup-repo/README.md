# 勤怠システム D1 自動バックアップ

毎日 03:00（日本時間）に、Cloudflare D1 の全案件のデータを書き出してこのリポジトリに保存します。

- **残すもの**：直近30日分は毎日の分、それより前は各月の最後の日の分（月末の状態に戻せます）
- **履歴の整理**：毎月1日に、gitの履歴を今あるファイルだけに作り直します（リポジトリが太り続けないように）
- **容量の確認**：毎日、全案件のデータベースの容量と、アカウントのデータベースの数を確認します。
  上限（1つ500MB・全部で10個。Cloudflareの無料プランの値）の8割を超えたとき、または容量や数を確認できなかったときは、
  バックアップは保存したうえで実行を「失敗」にします。GitHubから失敗のメールが届き、どの案件かは実行結果の Summary に出ます
  （有料プランに変えたときは、`backup.sh` の `MAX_DB_MB` / `MAX_DATABASES` を変更）

システム（Cloudflare）のデータそのものは消えません。何年前の記録も管理画面で見られます。
ここに残すのは、壊れたときに戻すための控えです。

**このフォルダの中身は、コードのリポジトリとは別の「非公開リポジトリ」で使ってください。**
バックアップには全従業員の名前・時給・打刻記録が入るため、外注などに共有するリポジトリには置かないでください。

## 最初の設定（1回だけ）

1. GitHubで**非公開（Private）**のリポジトリを新しく作る（例：`kintai-backup`）
2. このフォルダの中身（`.github` フォルダも含む）を、そのリポジトリにそのままコピーしてpushする
3. Cloudflareで APIトークンを作る
   - Cloudflareダッシュボード → 右上のアイコン →「マイプロフィール」→「APIトークン」→「トークンを作成」
   - 「カスタムトークンを作成」で、権限を **アカウント / D1 / 編集** にする
4. CloudflareのアカウントIDを確認する
   - ダッシュボードの「Workers & Pages」画面の右側に表示されている
5. 作ったGitHubリポジトリの Settings → Secrets and variables → Actions で、次の2つを登録する
   - `CLOUDFLARE_API_TOKEN`：手順3のトークン
   - `CLOUDFLARE_ACCOUNT_ID`：手順4のID
6. `databases.txt` に、バックアップするD1データベース名を1行に1つ書いてpushする
7. リポジトリの Settings → Branches で、既定のブランチ（main）に「強制push禁止」の保護をかけないでください
   （毎月の履歴の整理で使います）
8. GitHubの Actions タブ →「D1 daily backup」→「Run workflow」で一度手動実行し、
   `backups/<データベース名>/<日付>.sql.gz` ができることを確認する

新しい案件を追加したら、`databases.txt` に1行足すだけで翌日からバックアップされます。
失敗した日は、GitHubから登録メールアドレスに通知が届きます。

## すでに使っているリポジトリを更新するとき

このフォルダの `backup.sh` と `.github/workflows/d1-backup.yml` を、バックアップ用リポジトリに上書きコピーしてpushします。
次の日の 03:00 から新しい動きになります（古いファイルの整理もその日に行われます）。

## 復元するとき

Cloudflareが使えなくなった場合などは、新しいD1データベース（別アカウントでも可）を作って復元します。

```
npx wrangler d1 create <新しいデータベース名>
bash restore.sh backups/<データベース名>/<日付>.sql.gz <新しいデータベース名> <コードのリポジトリ>/schema.sql
```

- 復元先は**空のデータベース**にしてください
- ログイン情報はバックアップに含めていないため、復元後は打刻端末を管理者PINで登録し直してください
- Windowsでは Git Bash などから実行してください
